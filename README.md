# 消费记录助手（siyuan-plugin-expense-recorder）

一个思源笔记插件：**定时扫描「收集箱」笔记本中的图片和文字，通过 AI 自动识别为消费记录（金额、科目、时间、地点、商家、备注），并按消费发生的日期登记到对应日记文档中**（例如 2026 年 9 月 1 日的消费进入文档 `20260901`）。

## 功能特性

- ⏰ **定时自动处理**：可配置间隔（默认 30 分钟），也可点顶栏图标或命令随时手动触发；启动思源后自动开始
- 🖼️ **图片识别**：小票、支付截图、外卖/打车订单等，走视觉大模型（OCR + 理解一步完成）；本地 assets 图片与云端图床外链（如 `assets.b3logfile.com`）均支持
- 💬 **企业微信采集（可选）**：通过智能机器人长连接，把你在企微内部群里 @机器人 或单聊机器人发送的文字、图片、文件自动收集到收集箱，进入识别登记流程
- 📊 **数据库表格登记（可选）**：每天一张独立数据库表格存于当日文档（金额/科目/日期/时间/地点/商家/备注），汇总（当日总支出 + 科目占比）直接从当天表计算
- ✍️ **文字识别**：转账备注、消费清单等纯文字内容，走文本大模型
- 📅 **按天归档**：按消费实际发生日期（能理解"昨天""9月1日"等表述）写入 `{date}` 模板命名的文档，文档不存在会自动创建（父级路径也会逐级创建）
- 🏷️ **科目归类**：AI 优先从你自定义的科目列表（餐饮、交通、购物……）中归类
- 🔁 **防重复**：处理成功的块会打上 `custom-expense-processed` 属性，不会被二次识别；失败的块下一轮自动重试
- 🧾 **来源可溯**：每条记录附带跳回原块的链接

## 数据库表格登记（可选，默认关闭）

开启后，**每天一张独立数据库表格**：每日文档（如 支出记录/20260924）中自动创建当天的数据库表，记录直接写入当天表格（列：金额、科目、日期、时间、地点、商家、备注，全部自动创建），并在表格上方生成汇总：

```
当日总支出：¥42.00（共 2 笔）
科目占比：餐饮 ¥30.00（71%） · 交通 ¥12.00（29%）
```

汇总直接读当天表格计算（单日数据量小），不依赖任何主表。日期 → 表格的映射由插件持久化维护；删除文档后重开会自动重建表格视图（数据不丢）。无需任何手工配置，勾选启用即可。

## 企业微信智能机器人采集（可选，默认关闭）

在企微管理后台【协作 → 智能机器人】创建一个智能机器人（连接方式选**长连接模式**），把 **Bot ID** 和 **Secret** 填入本插件设置并勾选启用。之后：

- 把机器人添加进企微**内部群**，群里 **@机器人** 发送的文字/图片/文件会被自动收集；
- 或者直接**单聊机器人**发送（无需 @）；
- 收集的内容写入收集箱目录下的「企微-日期」文档（如 `/原始单据/企微-20260923`），并进入正常的 AI 识别登记流程。

**说明与限制**：

- 官方限制：智能机器人只能加入**内部群**（不支持客户群/外部群），且群聊中只有 @机器人 的消息会推送；单聊中所有消息都会收到
- 图片/文件通过企微的加密下载通道获取（URL 五分钟内有效），插件会自动下载、解密（AES-256-CBC）并保存为思源本地资产
- 长连接由插件在思源运行期间维持；**思源未运行期间发送的消息不会补收**
- 「只采集该成员 userid 发送的消息」填入你的企微 userid 后，群聊里其他人 @机器人的内容不会被收集
- 连接与采集状态可查看 `data/storage/petal/siyuan-plugin-expense-recorder/wecom-last.json`（订阅失败通常是 Bot ID / Secret 不对）

## 登记效果

在登记笔记本的 `/消费记录/20260901` 文档中，每条消费一个列表项：

```markdown
- **¥38.50** ｜ 科目：餐饮 ｜ 时间：2026-09-01 12:30 ｜ 地点：美团外卖 ｜ 商家：肯德基 ｜ 备注：午餐 ｜ [来源](siyuan://blocks/xxx)
- **¥12,800** ｜ 科目：购物 ｜ 时间：2026-09-01 21:05 ｜ 地点：京东 ｜ 备注：空气炸锅 ｜ [来源](siyuan://blocks/xxx)
```

## 安装

1. 在思源笔记中打开工作空间目录，把 `dist` 的内容放入：

   ```
   {工作空间}/data/plugins/siyuan-plugin-expense-recorder/
   ├── plugin.json
   ├── index.js
   ├── icon.png
   ├── README.md
   └── i18n/
       ├── zh_CN.json
       └── en_US.json
   ```

   （也可直接解压发布目录中的 `siyuan-plugin-expense-recorder-x.x.x.zip` 到 `data/plugins/` 下）

2. 重启思源（或在「设置 → 集市 → 已下载」中刷新），在「设置 → 插件」中启用「消费记录助手」。

## 配置

启用后进入「设置 → 插件 → 消费记录助手」点设置图标：

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| 收集箱笔记本 | 要扫描的笔记本（任意你用作收集箱的笔记本，如快速捕捉、手机分享、剪藏落地的笔记本） | 需选择 |
| 仅处理该路径下的文档 | 可选，如 `/收集箱`，留空处理整个笔记本 | 空 |
| 登记消费记录的笔记本 | 消费日记所在的笔记本 | 需选择 |
| 日记文档路径模板 | `{date}` 替换为 `20260901` | `/消费记录/{date}` |
| AI 接口地址 | 任何 OpenAI 兼容接口的 Base URL | 智谱 `https://open.bigmodel.cn/api/paas/v4` |
| API Key | 在对应平台申请 | 需填写 |
| 文本识别模型 | 识别纯文字 | `glm-4-flash`（智谱免费） |
| 图片识别模型 | 识别图片，需支持视觉 | `glm-4v-flash`（智谱免费） |
| 科目列表 | 「、」分隔，AI 优先从中归类 | 餐饮、交通、购物…… |
| 定时处理间隔（分钟） | 定时扫描周期 | 30 |
| 启动后自动定时处理 | 关闭则只手动触发 | 开 |
| 处理后的动作 | 给块打「已处理」属性 / 不标记 | 打标记 |

填好后点 **「测试 AI 连接」** 验证接口可用，再点 **「立即处理收集箱」** 试跑一轮。

> 💡 智谱开放平台的 `glm-4-flash`（文本）和 `glm-4v-flash`（视觉）为免费模型，注册后在 [open.bigmodel.cn](https://open.bigmodel.cn) 的「API 密钥」页面即可创建 Key，适合本插件的低频调用场景。也可以换成 OpenAI、SiliconFlow、one-api 中转等任何 OpenAI 兼容接口。

## 使用方式

- **自动**：启动思源后按设定间隔自动处理，处理结果通过顶部消息提示
- **手动**：点顶栏的钱包图标，或命令面板执行「立即处理收集箱」
- **流程**：每轮会扫描收集箱中未处理的块（单轮最多 50 条，防止触发模型限流，剩余的下一轮继续）→ 识别 → 登记 → 打标记。识别不出消费信息的内容（普通备忘等）也会直接标记为已处理，不会反复打扰

## 常见问题

**Q：测试连接报 `Failed to fetch` / CORS 错误？**
插件在思源窗口内直接调用 AI 接口，个别平台不允许浏览器跨域调用。请改用支持 CORS 的接口（智谱、OpenAI 官方接口均可），或用 one-api / new-api 等网关自建中转后把 Base URL 指向网关。

**Q：识别结果不对 / 科目不准？**
把常用科目补充进「科目列表」，模型归类会明显变准。必要时可换更强的模型（如 `glm-4.5v`、`gpt-4o-mini` 等）。

**Q：云收集箱（浏览器剪藏/微信收集）里的内容会被处理吗？**
本插件处理的是**笔记本内的块**。若使用思源云收集箱，请先把内容保存到收集箱笔记本中（保存时思源会让你选位置）。

**Q：块处理失败会怎样？**
失败的块不会打标记，下一轮定时会自动重试；连续失败可在思源开发者工具（`Ctrl+Shift+I`）控制台查看 `[expense-recorder] 失败详情`。

**Q：怎么确认插件真的跑过一轮？**
每轮处理（含空跑）都会把结果写入 `数据/data/storage/petal/siyuan-plugin-expense-recorder/lastrun.json`，包含扫描数、登记数、失败原因和时间戳。注意：**更新插件文件后需要完整重启思源**才会加载新版本（热重载对插件实例不一定生效）。

**Q：隐私？**
收集箱中待处理的**文字与图片内容会发送给你配置的 AI 服务商**用于识别，请自行评估敏感内容；除此之外插件不向任何第三方发送数据，配置只保存在本机插件数据目录。

## 开发

```bash
npm install
npm run dev      # 监听构建（改动后自动重建 dist）
npm run build    # 构建到 dist/
npm run check    # TypeScript 类型检查
npm run smoke    # 核心纯函数冒烟测试
```

调试时可将本目录软链接到 `{工作空间}/data/plugins/siyuan-plugin-expense-recorder`，重启思源并启用插件后即可加载 `dist/index.js`。

## 目录结构

```
src/
├── index.ts       # 插件入口：生命周期、定时器、命令、顶栏图标
├── settings.ts    # 设置对话框
├── processor.ts   # 扫描 → 识别 → 登记 → 标记 的处理流程
├── recognizer.ts  # AI 调用与提示词、结果解析
├── api.ts         # 思源内核 API 封装
└── types.ts       # 配置与记录类型
```
